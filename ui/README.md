# p-graph UI

Mock-first редактор pipeline на React, Material UI и React Flow.

Полная инструкция по запуску и troubleshooting:
[docs/frontend-runbook.md](../docs/frontend-runbook.md).

## Локальный запуск

Требуется Node.js 22 или новее. Для nvm версия закреплена в .nvmrc.

~~~bash
nvm use
npm ci
npm run dev
~~~

Открыть http://localhost:5173/?mock=true для локального редактора 0.2.
Адрес без параметров сохраняет подключение к HTTP API (`http://apiserver.local`),
добавленное в main. Если сервер недоступен, есть ссылка на локальный редактор.

Черновик хранится в localStorage браузера. Кнопка «Сбросить» удаляет локальный
черновик и возвращает демонстрационный граф из JSON-контракта.

## Проверки

~~~bash
npm run typecheck
npm test
npm run build
~~~

## Docker

~~~bash
docker build -t pgraph-ui:local .
docker run --rm -p 8080:8080 pgraph-ui:local
~~~

Приложение будет доступно на http://localhost:8080, health-check —
http://localhost:8080/healthz.

## Текущие mock-возможности

- каталог 0.2: файловый вход, Python кубик, консоль и return;
- добавление кликом или drag-and-drop, перемещение, настройка и удаление узлов;
- соединение совместимых портов: несколько стрелок в один вход и разветвление одного выхода на несколько входов;
- настройка имён, типов и лимитов входов и выходов Python/return;
- Python-редактор CodeMirror с подсветкой, отступами и undo/redo;
- версия Python и список зависимостей в настройках кубика, валидация и экспорт в JSON;
- вкладка «Логи» выбранного кубика с демонстрационным запуском;
- автоматическое обновление сохранённого черновика 0.1 → 0.2 при загрузке;
- удаление стрелки: клик по связи → «Удалить стрелку», либо Delete / Backspace;
- сохранение черновика в localStorage;
- mock-валидация правил запуска;
- просмотр, копирование и скачивание backend JSON.

HTTP API уже подключён через HttpPipelineRepository. Локальный режим явно
выбирается `?mock=true`; пример control всегда использует локальный репозиторий.
Расширения 0.2 пока проверяются на моках, backend-реализация отдельно.
Canvas и доменная модель от транспорта не зависят.


## Свой кубик

Добавьте «Python кубик», выберите его и откройте «Редактировать входы» /
«Редактировать выходы». Укажите имена и типы портов. Пустой максимум связей
разрешает несколько стрелок в один пин; такой вход поступает в Python списком.
В «Редактировать Python-код» задайте функцию `run(inputs)`, возвращающую словарь
по именам выходов. Нажмите «Готово», затем «Сохранить» для записи черновика.

В `return` выходы обозначают результаты pipeline и выбирают вход-источник.
Код сохраняется и экспортируется в JSON, выполнение пока не подключено.
Логи помечены как демонстрационные и не зависят от редактирования кода.

[Полный контракт 0.2](../docs/pipeline-backend-json-format.md).

## Параллельные ветки

Проведите стрелку из выхода «Файл» к первому Python-кубику, затем из того же
выхода — ко второму. Первая связь сохранится. Оба кубика получат тот же файл;
их результаты можно соединить с входами return. Стрелки между самими ветками
не требуются. Разветвление не меняет формат 0.2 и не требует обновления черновика.

## Пример с control

Кнопка «Пример control» открывает отдельный граф в новой вкладке:
http://localhost:5173/?example=control. Его черновик сохраняется независимо
от основного графа.

`Подготовить текст —text→ Напечатать текст —control→ После вывода в консоль —text→ return`

У консоли выход `done: control`, у следующего Python-кубика вход
`printed: control`. Стрелка требует дождаться завершения печати; текст по ней
не передаётся. Посмотрите Python-код следующего шага, JSON графа и demo-логи.
Проверка графа проходит без загруженного файла. Реального выполнения пока нет.

## Модули и зависимости Python

В настройках Python-кубика выберите «Версия Python» и при необходимости
заполните «Зависимости Python», по одной строке на пакет:

```text
requests==2.32.5
```

Пустой список означает отсутствие дополнительных пакетов. Стандартную
библиотеку (`json`, `math` и т. п.) добавлять не нужно — пишите обычный import
в коде. Extras поддерживаются в форме `requests[socks]==2.32.5`.

В JSON эти настройки находятся в `implementation.pythonVersion` и
`implementation.requirements`. Версия по умолчанию — 3.12, зависимости — [].
Поля необязательные, формат остаётся 0.2; старые документы не требуют обновления.
Смена кода не сбрасывает окружение. «Проверить» покажет неверный формат или
дубликаты пакетов; черновик с ошибками можно сохранить.

Frontend сохраняет настройки. Наличие пакетов, разрешение зависимостей,
установка и исполнение будут проверяться будущим backend runner.
[Подробный контракт](../docs/pipeline-backend-json-format.md#окружение-и-зависимости-python).
